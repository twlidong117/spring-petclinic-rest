## 一、准备：用可控制的服务返回值隔离控制器行为

测试替身是代替真实依赖、方便控制测试条件的对象。该类用 `@MockitoBean` 为 `ClinicService` 设置 Mockito 测试替身；控制器和 Mapper 通过 `@Autowired` 取得，没有在这里被替换为测试替身。

`@BeforeEach` 表示每个测试开始前执行准备方法。这里创建新的列表，依次加入 cat、dog、lizard、snake 四个 Java 对象，并构造 MockMvc。它们的编号和名称由测试代码赋值，不是通过服务从数据库查询得到。

成功场景先执行：

```java
petTypes.remove(0);
petTypes.remove(1);
given(this.clinicService.findAllPetTypes()).willReturn(petTypes);
```

列表下标从 0 开始。第一次删除 cat，列表变为 dog、lizard、snake；第二次删除此时下标 1 的 lizard，剩下 dog、snake。删除对象只改变内存列表，不删除数据库记录。

`given(...).willReturn(...)` 预设行为：控制器稍后调用服务替身的该方法时，返回这个列表。这一行本身不是响应检查，也不调用真实服务去查询数据库。

## 二、执行：在测试进程内模拟请求

```java
this.mockMvc.perform(get("/api/pettypes")
    .accept(MediaType.APPLICATION_JSON))
```

MockMvc 是在测试进程内驱动 Spring 请求处理的工具，使用模拟请求和响应对象，不依赖真实服务器监听端口。本例用 `standaloneSetup(petTypeRestControllerV1)` 围绕指定控制器搭建处理环境，并配置异常处理器。

`get(...)` 构造读取请求；`accept(...)` 表达客户端希望接收 JSON；`perform(...)` 执行模拟请求。这里使用 `/api/pettypes`，不应照搬第九步真实服务器地址中的端口和 `/petclinic` 应用前缀。

该测试类还有 `@SpringBootTest`，会加载 Spring 测试上下文，因此不能称为完全不加载 Spring 的纯对象测试；同时也不能因这个注解就认定本次 MockMvc 请求通过真实网络发出。

## 三、检查：断言是必须满足的条件

断言（assertion）就是测试要求结果满足的条件；不满足时测试失败。成功场景包括：

```java
.andExpect(status().isOk())
.andExpect(content().contentType("application/json"))
.andExpect(jsonPath("$.[0].id").value(2))
.andExpect(jsonPath("$.[0].name").value("dog"))
.andExpect(jsonPath("$.[1].id").value(4))
.andExpect(jsonPath("$.[1].name").value("snake"));
```

- `isOk()` 检查响应状态为 200。
- `contentType(...)` 检查实际响应内容类型，与请求中的 `accept(...)` 分工不同。
- `jsonPath(...)` 用路径表达式定位 JSON 中的数据；`$` 表示整个响应内容，`[0]` 是第一项，`.name` 是其 name 字段。
- `.value("dog")` 检查响应中第一项名称确实等于 dog，不会把响应内容改成 dog。
- 这些断言检查前两项的编号与名称，没有单独断言列表长度恰好为 2；测试覆盖范围由实际断言决定。

## 四、空集合场景

`testGetAllPetTypesNotFound()` 先 `petTypes.clear()`，再预设服务返回空列表，执行同一路径请求并用 `status().isNotFound()` 检查 404。这里验证当前控制器的空结果分支，不模拟数据库连接失败。

## 五、能证明什么，不能证明什么

若这些测试实际执行通过，可证明在设置好的服务返回值和测试环境下，对应控制器响应满足列出的断言。真实控制器、对象映射和响应文本生成参与这条处理流程；服务查询链路被替身截断。

不能由这些响应断言推断数据库存在 dog、snake，不能证明真实服务和数据访问查询正确、端口可用或所有接口正常。测试上下文可能初始化其他组件；服务替身截断查询不等于整个测试进程绝不接触数据库。

测试名称和 `@WithMockUser` 包含角色信息，但本步未审查完整安全配置与过滤器链，也未验证越权拒绝，不据此宣称认证授权完整可用。

## 六、官方文档与面试题

- [Spring MockMvc](https://docs.spring.io/spring-framework/reference/testing/mockmvc.html)：通过模拟请求和响应对象执行请求处理。
- [Spring @MockitoBean](https://docs.spring.io/spring-framework/reference/testing/annotations/integration-spring/annotation-mockitobean.html)：用 Mockito 测试替身替换测试上下文中的依赖。

1. **预设服务返回值和响应断言有什么区别？** 前者准备条件，后者检查执行后的真实测试响应；预设不会保证控制器一定正确返回。
2. **MockMvc 测试通过能证明服务器端口正在监听吗？** 不能。这里通过进程内的模拟请求执行处理，不访问真实监听端口。
3. **为什么检查状态码后还要检查内容？** 状态码正确时，字段仍可能错误或缺失；内容断言能发现状态码检查覆盖不到的问题。
4. **为什么返回 dog、snake 不能证明数据库中有这些记录？** 数据由测试准备方法在内存创建，再由服务替身返回，没有经过真实服务查询链路。
