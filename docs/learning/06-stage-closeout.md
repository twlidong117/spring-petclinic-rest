Maven 的测试命令会依照生命周期自然执行测试之前的阶段，其中包括必要的主代码编译。这是测试步骤的正常组成部分，不应被拆成又一次“独立编译复验”任务，也不改变第四、第五步已经留存的编译证据。

## 知识点

1. `BUILD SUCCESS` 只说明被调用的那次 Maven 生命周期目标成功完成；必须结合命令、阶段与测试报告判断测试是否执行及通过。
2. 构建工具运行所用 Java 与编译目标是两个维度；较新的 Java 开发工具包可以按 `release 17` 生成 Java 17 目标字节码，但不能使用目标版本不支持的语言特性或平台接口。
3. 网络故障应区分域名解析、代理连接、代理策略、源站响应及文件存在性；不同客户端还可能使用不同代理配置。
4. 生成的 API 接口源码是编译输入，不等于业务实现；插件生成、源码目录注册和编译是不同环节。
5. `test` 比 `compile` 进入更后的生命周期阶段，可能需要额外测试依赖和插件，因此离线编译成功不能保证离线测试资源完整。

## 面试题及答案

### 1. 为什么不能仅凭 `BUILD SUCCESS` 判断测试通过？

**答案：**它只表示本次请求执行的 Maven 目标成功。若命令只执行到 `compile`，测试阶段不会因此被证明执行；即使进入测试阶段，也应结合测试插件输出、报告和进程退出状态确认结果。

### 2. Java 21 运行 Maven 时，为什么项目仍可能以 `release 17` 编译？

**答案：**Java 21 描述构建工具进程使用的运行环境，`release 17` 描述编译器接受的平台接口和目标字节码版本。两者可以不同，但源码不能使用 Java 17 目标不支持的正式语法和接口。

### 3. `UnknownHostException` 与代理返回 `403` 分别说明什么？

**答案：**前者表示相应客户端没有把主机名解析为可用网络地址；后者表示客户端已经到达代理，但代理拒绝请求或连接策略。它们都不能单独证明目标文件不存在。

### 4. OpenAPI Generator、Build Helper 和 Maven Compiler Plugin 如何配合？

**答案：**OpenAPI Generator 从接口描述生成 Java API 接口与数据传输对象；Build Helper 把生成目录登记为项目源码目录；Maven Compiler Plugin 再编译生成源码和手写源码。生成接口不是业务实现。

### 5. 为什么离线 `compile` 成功不保证离线 `test` 成功？

**答案：**测试还可能需要测试范围依赖、测试代码编译和测试插件；这些组件不一定在主代码编译时使用或已进入本地缓存，测试代码与断言本身也可能失败。
